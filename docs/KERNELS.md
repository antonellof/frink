# Kernel coverage

Generated by `frink caps --kernels --write docs/KERNELS.md` from the
dispatch tables (`frink_core::kernel_matrix`); do not edit by hand.
`cargo test -p frink-core kernel_matrix` fails when this file and the
dispatch disagree. Tracked in #405, decided in
[ADR 0010](adr/0010-coverage-before-speed.md).

- `kernel`: a kernel for this kind and op runs on the backend.
- `loop`: no kernel of this shape; the work stays on the backend as
  one matvec per position.
- `HOST`: the work runs on the host CPU and the backend is idle for it.
  The output is still correct, which is why it reads as a slow row.
- `f32` (CPU only): no integer `vec_dot` for this kind, so the weight
  is dequantized into an f32 dot.

## Reading the CPU column

The CPU column reads the kind table, not one host's tier. Which half
of the integer tier a host takes is decided at run time
(`FRINK_CPU_INT_DOT`, and the x86 matvec half is off by measurement), so
a `kernel` cell is the best path the build has for that kind.

## Reading the get_rows column

Metal's gather runs inside the fused decode stack, for a model with no
embedding scale or norm. Everywhere else the embedding row is
`WeightMatrix::dequant_row` on the host, one row per token.
