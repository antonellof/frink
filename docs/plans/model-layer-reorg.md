    content: "THE ANSWER TO 'what is the per-architecture unit, concretely, in frink terms', and it is TWO TIERS because frink already has two and both are load-bearing. TIER A, the common case, is a MODULE `crates/frink-models/src/arch/<name>.rs` holding one zero-sized type that implements a three-method `Arch` trait, named after llama.cpp's three virtuals because the mapping is 1:1 and a reviewer benefits from the correspondence: `hparams(&self, &ShardedGguf, &mut ModelConfig)` (llama.cpp `load_arch_hparams`, llama-model.h:747; FreeToken `parse_config`, models/register.py `ModelSpec.parse_config`), `tensors(&self, &ShardedGguf, layer, &mut LayerBuild)` (llama.cpp `load_arch_tensors`, llama-model.h:748; FreeToken `iter_weights`), and `layer_plan(&self, &ModelConfig, layer, &LayerWeights) -> Result<LayerPlan, LoadError>`. The third one is where frink MUST diverge from llama.cpp and follow FreeToken instead. llama.cpp's `build_arch_graph` returns a `unique_ptr<llm_graph_context>` holding a ggml graph, which `llama_context::process_ubatch` then CACHES and reuses across tokens (`llm_graph_result::can_reuse`, llama-graph.cpp:1378; `build_graph` called at exactly one site, llama-context.cpp:1354). Frink has no graph object and executes eagerly, so there is nothing to amortise a per-token virtual call over and no `build_arch_graph` to port. `layer_plan` therefore returns DATA built once at load, which the one shared runner reads. TIER B, for a genuinely different graph, is a module implementing the EXISTING `Engine` trait (engine.rs:243-252). That tier already exists and works: `kimi_decoder.rs` (1037), `glm52_decoder.rs` (436), `deepseek_v4_decoder.rs` (922), `gemma4_engine.rs` (485), `MlaEngine` (engine.rs:346), plus five refusal stubs (`minimax_engine.rs` 58, `llama4_engine.rs` 43, `hybrid_engine.rs` 68, `recurrent_engine.rs` 37, `t5_engine.rs` 34). This plan proposes NO change to Tier B's shape and says so deliberately, because the instruction is to extend what exists rather than invent a parallel mechanism. Note honestly what Tier B does NOT get today: `Engine` carries only `forward_token`, so a Tier-B architecture has no batched prefill, no paged KV and no prefix cache. `frink-server::generate` takes `&Decoder` concretely (generate.rs:200, :307, :388, :741) and `generate_engine` (generate.rs:1203) is the degraded fallback loop. # Model layer reorg: make adding an architecture a new file

> This is the plan north-star's `t1-scale-the-model-layer` points at as
> `model-registry-reorg.md`. That file was never written.

## The number, and what it is made of

`crates/frink-models/src/decoder.rs` was **6438 lines** when this was
measured. Code ran to 4842; the rest was its own test module. It grew
to 8050 lines before #390 split it (and `loader.rs`, then 6024) into
modules on 2026-10-28; `decoder.rs` is 254 lines now and the bodies
live under `decoder/`. The `attn.rs` line numbers below are from the
original measurement and have moved; the shape they describe has not.

When this was measured, four host functions each contained a complete
decoder layer written out longhand:

| function | now in | shape |
|---|---|---|
| `forward_token` CPU arm | `decoder/forward_token.rs` | one row, contiguous KV |
| `forward_token_paged` | `decoder/paged.rs` | one row, paged KV |
| `forward_hidden_batch_inner` | `decoder/batch.rs` | n consecutive positions, two arms |
| `forward_multi_seq_kv` | `decoder/multi_seq.rs` | n independent sequences |

Steps 0 and 1 below have landed: the attention half of the layer is one
`attn_block` taking a `KvStep` (`decoder/attn_block.rs`), shared by the
contiguous, paged and multi-sequence bodies.

`crates/frink-metal/src/attn.rs` is **9026 lines** and holds seven
more, one per fused launch (`attn.rs:5311, :5439, :5657, :5928, :6890,
:7082, :7238`).

**Eleven copies of one decoder layer, across two crates.**
`post_ffn_norm` is applied at seven separate sites inside
`forward_hidden_batch_inner` alone.

## What that costs, on the record and newly found

Already recorded: the paged decode loop had **lost five model
features** by being a copy of the contiguous one, three of them wrong
on CPU too. PR #22 hit the same shape from the other side and fixed it
by making `forward_multi_seq` take a `MultiSeqKv` parameter rather than
growing a paged twin (commit `c5aa646`; the reasoning is on
`MultiSeqKv` in `decoder/multi_seq.rs`).

Found while writing this plan, and it is the argument in miniature:

- `attention_scale` is applied in `forward_token`'s CPU arm and in
  `forward_token_paged`. **Nowhere else.** Batched prefill and the
  multi-sequence path do not apply it.
- It is unreachable today only because the loader hardcodes
  `let attention_scale = None;`, and `unsupported_scaling_keys` refuses
  a file carrying a non-noop `*.attention.scale`.
- The guard test that exists,
  `the_paged_path_keeps_every_per_layer_feature_the_contiguous_one_applies`
  (now in `decoder/tests/paged.rs`), sets `attention_scale = Some(0.37)` and compares
  the two paths that **agree**, never the two that do not.

A sixth gap, latent behind a loader refusal, invisible to the test
written specifically to catch this class. That is what "nothing
notices" looks like.

## Two references, one unit each

Neither replaces the other.

| | FreeToken | llama.cpp | oxillama |
|---|---|---|---|
| per-arch unit | package (5-10 files) | one `.cpp` + a decl | directory (5-6 files) |
| simple arch | `llama/` **280 lines** | `llama.cpp` **250** | `llama/` **2845** |
| complex arch | `deepseek_v4/` **2039** | `deepseek4.cpp` **1546** | `mamba2/` **3364** |
| per-arch average | ~800 | **~232** | **~2110** |
| shared vocabulary | OP objects, `layers/` 1623 | **block builders**, `build_attn`/`build_ffn` | primitives only |
| registration | one dict row | enum + name + decl + `case` | one `register()` line |
| unknown arch | `ValueError` | **throws twice** | `None` |
| config + weights | **own registry slots** | own virtuals | inside the arch |

oxillama is the control experiment: same language, same problem, split
per-arch **without** block helpers, and it pays 2,110 lines per
architecture because every arch inlines its own attention loop
(`oxillama-arch/src/llama/model.rs:332`, ~187 lines).

**So: vocabulary first, split second.** Splitting before the block
helpers exist lands on oxillama's number, not llama.cpp's.

## The unit, in frink terms

**Tier A**, the common case, `crates/frink-models/src/arch/<name>.rs`,
one ZST implementing three methods:

```
hparams(&self, &ShardedGguf, &mut ModelConfig)      // load_arch_hparams / parse_config
tensors(&self, &ShardedGguf, layer, &mut LayerBuild) // load_arch_tensors / iter_weights
layer_plan(&self, &ModelConfig, layer, &LayerWeights) -> LayerPlan
```

The third diverges from llama.cpp on purpose. `build_arch_graph`
returns a ggml graph that `llama_context` then **caches and reuses
across tokens** (`llama-graph.cpp:1378`, `llama-context.cpp:1354`).
Frink executes eagerly and has no graph object, so there is nothing to
amortise a per-token virtual call over. `layer_plan` returns **data
built once at load** that one shared runner reads.

**Tier B**, a genuinely different graph, is the **existing** `Engine`
trait (`engine.rs:243`). Kimi, GLM-5.2, DeepSeek-V4, MLA and Gemma-4
already live there. This plan proposes no change to its shape.

## The order

```
0  decoration audit          done
1  one attn_block            done: decoder/attn_block.rs, KvStep
   file split                done in #390 (decoder/, loader/ modules)
2  LayerPlan                 built at load; finishes the dead ExecutionPlan
3  trait Arch + arch/        plain_gqa and gpt_oss, with oxillama's fallback recipe
4  weight-iterator seam      one loader, per-arch name tables (7 loaders, 10,135 lines)
5  registry inversion        generic GQA stops being the shortest thing to write
6  Metal stacks read LayerPlan
   ---- then ----
   deepseek4                 the first Tier-B arch under the new structure
```

Steps 1 through 3 are separately landable and separately verifiable.
Step 1 touches three call sites and adds no types.

## Verification, ranked by proof per byte

1. **Bit-identity against the previous path.** `assert_eq!` on logits,
   not a tolerance. Needs no new artifact. Primary gate for steps 1-3.
2. **Synthetic fixtures**, 23-103 KB, already in
   `crates/frink-models/tests/fixtures/`. New rule: an `Arch` impl
   lands with one, enforced by making the fixture an **argument** to
   the registry helper.
3. **Real checkpoints already on disk.** `models/` is 46 GB, 27 GGUFs,
   named in `benchmarks/suite.json`. Steps 1-3 touch nothing outside it.
4. **`frink parity` + `tools/llama_logits.c`.** Needed from step 4,
   where a new architecture has no previous frink to match.
5. **`frink bench` receipts** on Metal `tg128` and CPU `tg128`, every
   step that touches a hot path.

And **sabotage-check everything**, as `c5aa646` already did. A guard
that cannot fail is how five features went missing.

## The dispatch budget

| where | cost | verdict |
|---|---|---|
| per model, at load | one `&'static dyn Arch` | free |
| per layer, per forward | `LayerPlan` field reads, two `match`es | same as today |
| per token | one vtable hop, Tier B only | fine (oxillama does this) |
| **inside the layer loop** | `Box<dyn>`, closures | **rejected** |
| **per op / head / element** | any trait object | **rejected** |
| **below load** | any arch string compare | **rejected** (`capability.rs:10-12`) |
| **inside `launch_decode_dense_stack`** | anything at all | **rejected** |

Metal is at parity and 8 of 12 decode rows are ahead of llama.cpp.
`launch_decode_dense_stack` (`frink-metal/src/attn.rs:5928`) folding
every layer into one command buffer is what those rows rest on.
`LayerPlan` decides **whether** to take that path. It is never read
inside it.

- Whether the Metal fused stack can be gated from `LayerPlan` without

- Whether `ArchProfile` keeps its derives with a `dyn` field
